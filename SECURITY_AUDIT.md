# Security Audit Report

| Finding | File/Location | Severity | Recommended Fix |
|---|---|---|---|
| Hardcoded JWT_SECRET in environment / code check | `server/src/routes/auth.ts`, `server/src/utils/authMiddleware.ts` | High | Ensure `JWT_SECRET` is never checked into version control. It is currently pulled from `process.env.JWT_SECRET`, which is good, but ensure `.env` files are in `.gitignore`. |
| Unauthenticated sensitive route | `server/src/index.ts` (Admin endpoints) | Critical | The admin endpoints (`/api/admin/finances`, `/api/admin/users`, `/api/admin/coaches/pending`, `/api/admin/coaches/:id/approve`, `/api/admin/notifications`) lack any authentication or authorization checks. Apply `authenticateJWT` and check for `req.user.role === 'ADMIN'`. |
| Unauthenticated Patient Assessment Endpoint | `server/src/index.ts` (`POST /api/assessments`) | Medium | This creates a temporary user account with a hardcoded password hash (`temp-hash`) and temporary email. This allows mass account creation and spam. Add rate limiting, CAPTCHA, or require an initial verified phone number via OTP. |
| Insecure File Upload (S3) | `server/src/utils/s3.ts` | High | Uploaded files (health assessments/videos) are set with `ACL: "public-read"`. This exposes sensitive patient health data (PII) to the public internet. Change ACL to `private` and use presigned URLs for authorized access only. |
| Mocked Zarinpal Payment Integration | `server/src/routes/payment.ts` | Critical | The Zarinpal payment integration is fully mocked. There is no environment-based switch (like `NODE_ENV === 'production'`) to enforce real verification. Before production use, verify the real integration doesn't skip amount/signature verification, and remove or strictly gate the mock gateway endpoints (`/mock-gateway`, `/verify`). |
| Mocked Authentication / Hardcoded Values | `server/src/routes/auth.ts` | Critical | The `/login` endpoint currently bypasses password validation completely and only checks if the email exists. Implement real password hashing (e.g., bcrypt) and comparison. |
| JWT Token Storage in LocalStorage | `src/components/ChatDashboard.tsx`, `src/App.tsx`, `src/pages/protected/PatientPortal.tsx`, `src/pages/protected/CoachPortal.tsx` | High | JWTs are stored in `localStorage`, making them vulnerable to XSS attacks (e.g., in the chat feature). Move token storage to HttpOnly, Secure cookies. |
| Insecure WebSocket Room Joining | `server/src/index.ts` (`socket.on('join')`) | High | Any user can join any WebSocket room by providing an arbitrary `userId` and receive messages for that user. Enforce authentication on the WebSocket connection and only allow joining the room matching the authenticated user's ID. |
| Insecure Direct Object Reference (IDOR) / Missing Sender Auth | `server/src/index.ts` (`socket.on('sendMessage')`) | High | The socket event trusts the `senderId` provided by the client. An attacker can spoof messages from other users. Authenticate the socket and pull `senderId` from the authenticated session, not the client payload. |
| Potential XSS in Chat | `src/components/ChatDashboard.tsx` (Assumed) | High | Since real-time chat is implemented, ensure all incoming `content` from `newMessage` events is properly sanitized before rendering in React (React usually escapes text, but ensure no `dangerouslySetInnerHTML` is used or unescaped markdown). |
| Overly Permissive CORS | `server/src/index.ts` | Medium | `app.use(cors())` and `io` with `origin: '*'` allow any domain to make requests. Restrict `origin` to the specific frontend domains. |
| Missing Input Validation | Across all `server/src/routes/` | Medium | Lack of robust input validation (e.g., using Zod/Joi) for incoming req.body/req.query data before passing to Prisma, risking application crashes or logic errors (though Prisma mitigates SQLi). |
| Dependency Vulnerabilities (npm audit) | `node_modules/` (root and `server/`) | High | Found multiple High/Critical vulnerabilities including `socket.io-parser` (Memory Exhaustion), `react-router` (CSRF bypass), and `fast-uri` (Host confusion). Run `npm audit fix` and update vulnerable dependencies in both root and `server/`. |
| Missing Authorization (IDOR) | `server/src/routes/payment.ts` (`POST /checkout`) | High | The `/checkout` endpoint accepts a `userId` in `req.body` without verifying if it matches the authenticated user. It also doesn't require authentication. Attackers can initiate payments or associate transactions with arbitrary user IDs. Apply `authenticateJWT` and extract `userId` from the token. |
